## 摘要
检索外部知识的 LLM 智能体通常先生成文本形式的搜索查询，然后运行一个独立的嵌入模型将其编码为向量。这种双模型流水线增加了基础设施的复杂性和延迟，且具有冗余性：LLM 已经在其隐藏状态中编码了完整的对话上下文。我们提出通过添加一个轻量级的投影头，将隐藏状态直接映射到嵌入空间，从而赋予 LLM 智能体原生检索能力，消除了对独立嵌入模型的需求。通过结合对齐损失、对比损失和排名蒸馏损失进行训练，我们的方法在保留了 97% 基准检索质量的同时，使 LLM 智能体能够利用其自身的表示进行搜索。在 QReCC 对话搜索基准上的实验表明，与标准的“生成后编码”流水线相比，该方法具有竞争力的 Recall@10 和 MRR@10，系统性的消融实验证实了各损失组件的贡献。

## Abstract
LLM agents that retrieve external knowledge typically generate a search query as text, then run a separate embedding model to encode it into a vector. This two-model pipeline adds infrastructure complexity and latency, yet is redundant: the LLM already encodes the full conversational context in its hidden states. We propose equipping LLM agents with native retrieval capability by adding a lightweight projection head that maps hidden states directly into the embedding space, eliminating the need for a separate embedding model. Trained with a combination of alignment, contrastive, and rank distillation losses, our method retains 97\% of baseline retrieval quality while enabling the LLM agent to search with its own representations. Experiments on the QReCC conversational search benchmark show competitive Recall@10 and MRR@10 compared to the standard generate-then-encode pipeline, with systematic ablations confirming the contribution of each loss component.

### 1. 核心问题与整体含义
*   **研究动机**：在传统的 RAG 流程中，LLM 智能体需要先生成文本查询（Query），再由一个独立的嵌入模型将其编码为向量。作者认为这种“双模型”架构存在**冗余**：LLM 在生成查询时已经通过隐藏状态（Hidden States）理解了完整的对话上下文，而将其转化为文本再重新编码不仅增加了系统复杂度和延迟，还会造成信息损失。
*   **核心目标**：探索是否可以直接从 LLM 的内部隐藏状态中提取检索向量，从而实现“一个模型就够了”的高效架构。

### 2. 方法论
*   **核心思想**：在 LLM 的最后一层隐藏状态上添加一个轻量级的**投影头（Projection Head）**，将其直接映射到现有的嵌入空间中。
*   **关键技术细节**：
    *   **隐藏状态提取**：在 LLM 正常生成查询的过程中，保留非特殊 Token 的最后一层隐藏状态序列。
    *   **投影头架构**：包含一个线性输入层、一个 2 层的 Transformer 编码器（用于捕捉 Token 间的依赖）、均值池化层（Mean Pooling）以及一个带 L2 归一化的线性输出层。总参数量约 25M，远小于 8B 的 LLM。
    *   **训练目标（知识蒸馏）**：使用三个损失函数联合训练：
        1.  **对齐损失（Alignment Loss）**：最小化投影向量与教师嵌入模型输出之间的角度距离。
        2.  **对比损失（Contrastive Loss）**：通过 InfoNCE 损失保持批次内查询的判别性结构。
        3.  **排名蒸馏损失（Rank Distillation Loss）**：利用 KL 散度使投影头学习教师模型对文档候选集的排名偏好。
*   **流程**：训练时使用教师模型进行蒸馏；推理时直接丢弃教师模型，仅靠投影头输出向量进行检索。

### 3. 实验设计
*   **数据集**：使用 **QReCC**（对话上下文中的问题重写）基准测试集，包含多轮对话及相关的文档标注。
*   **实验场景**：同系列模型设置，使用 **Qwen3-8B** 作为 LLM 智能体，**Qwen3-Embedding-8B** 作为教师嵌入模型。
*   **对比方法（Baseline）**：标准的“生成后编码”流水线（LLM 生成文本 -> 嵌入模型编码）。
*   **评估指标**：Recall@10、MRR@10、nDCG@10 以及推理延迟。

### 4. 资源与算力
*   **硬件环境**：单张 **NVIDIA RTX PRO 6000** GPU（Blackwell 架构，98GB 显存）。
*   **训练时长**：
    *   初始隐藏状态轨迹（Trace）生成：约 2 小时。
    *   投影头训练：利用缓存的轨迹，每次运行仅需 **15-20 分钟**。
*   **超参数**：最佳配置为 80 个 Epoch，学习率 $2 \times 10^{-4}$，采用余弦退火。

### 5. 实验数量与充分性
*   **实验规模**：共进行了 **12 组** 不同的消融实验配置，涵盖了损失组件的组合、学习率敏感度、训练时长以及排名蒸馏的超参数调节。
*   **充分性与客观性**：
    *   作者使用了 **McNemar 检验** 进行显著性分析，并计算了 95% 的自助法（Bootstrap）置信区间，确保结果的统计可靠性。
    *   通过系统性的消融实验证明了三个损失函数缺一不可（尤其是对齐损失是基础）。
    *   实验设计较为严谨，但目前仅限于单一模型系列和单一数据集。

### 6. 主要结论与发现
*   **性能接近无损**：该方法保留了基准模型 **97%** 的检索质量（Recall@10 从 0.637 降至 0.607）。
*   **延迟大幅降低**：推理延迟从 43.5ms 降至 2.0ms，实现了约 **21.8 倍** 的加速。
*   **损失函数作用**：对齐损失贡献最大；排名蒸馏损失不能独立存在，但在有对齐基础时能显著提升局部排名质量。
*   **优化敏感性**：投影任务对学习率非常敏感，较长的训练时间和较低的学习率是成功的关键。

### 7. 优点
*   **架构极简**：消除了 RAG 系统中维护两个大模型的负担，降低了基础设施成本。
*   **高效性**：利用了 LLM 已有的计算结果，投影头带来的额外计算开销几乎可以忽略不计。
*   **端到端潜力**：为未来实现完全端到端的检索-生成联合优化铺平了道路。

### 8. 不足与局限
*   **泛化性验证不足**：仅在 QReCC 数据集上测试，尚未验证在跨领域或长文档检索中的表现。
*   **同族模型偏见**：实验中 LLM 和嵌入模型属于同一家族，可能存在预训练阶段的表示重叠，跨家族模型（如用 Llama 投影到 OpenAI 空间）的效果尚不可知。
*   **训练仍需教师**：虽然推理时不需要嵌入模型，但训练阶段仍需运行教师模型来获取目标向量。
*   **微小性能差距**：尽管差距很小，但在统计学上仍显著低于基准模型，对于追求极致精度的场景可能仍需权衡。
